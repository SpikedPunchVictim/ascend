# EV-74: does a stratified sample make a model classify better than a random one of the same size?

**Status**      Measured 2026-10-20/21 for `asc-asq`, and the first of this project's empirical beads
                to be **pre-registered before any arm ran** (`spike/asq/PREREG.md`, written after the
                learnability pilot and before the first draw). The corpus question `EV-22` left open
                on 2026-09-22 — it could not state a corpus property that would make the experiment
                runnable — is answered: the property now exists, it is named below, and the
                experiment was run on it.

**Question**    `asc-asq`: *"Does stratified sampling actually improve LLM classification accuracy
                over random?"* with the bead's own decision rule, *"if stratified shows no advantage,
                DROP the mode rather than carry it."*

## Method

**Corpus.** Every finding a reviewer reported through `ReportFindings`, read from the raw
transcripts rather than from a store (`spike/asq/extract.mjs`): 422 rows, 43 of them a resumed
session writing the same finding twice, **n = 379**, sha256 `f170dbe8…`. Every row carries the
reviewer's `summary`, its `failure_scenario`, and the lens it filed the finding under. This is the
route `EV-22` did not have: it needed text the label is inferable from, and the type that had the
volume (`tool_denial`, 912 entries) still carries none — its `tool_name` is `Bash` for 91 % of rows.

| class | n | share |
|---|---|---|
| boundary_conditions | 119 | 31.4 % |
| assumption_audit | 74 | 19.5 % |
| cross_implementation_divergence | 70 | 18.5 % |
| state_machine | 33 | 8.7 % |
| error_paths | 31 | 8.2 % |
| data_lifecycle | 25 | 6.6 % |
| write_read_asymmetry | 13 | 3.4 % |
| time_concurrency | 12 | 3.2 % |
| environment_divergence | 2 | 0.5 % |

**Split** (seed 20261020, fixed before any draw): half of each class is the test set (192 items),
the rest the pool (187). The test set never enters the sampler's store — verified, not assumed: 187
rows in the scratch store, **0** of the 192 test items among them, **0** rows outside the pool.

**Sampler.** The real one under test. The pool is recorded into a scratch store as `asq_item`, and
each draw is `asc explore asq_item --sample <arm> --by class --limit 20 --seed <seed+d>`; the same
seed feeds both arms of a draw, so the only difference is the sampler. Seeded draws reproduce
exactly (checked by running one twice).

**Arms.** 20 labelled examples (`random`: uniform without replacement; `stratified`: with the floor
`asc-1bd` measured), the nine lenses named in both prompts, the same 192 test items in the same
order, one call per (draw, arm): `deepseek-v4.1-flash:cloud`, 10 draws per arm, 20 calls.

The sampler's half of this is not a model result and is exact: **the random prompt omitted 1–3 of
the nine lenses in every one of the 10 draws (21 omissions, mean 2.1); no stratified prompt omitted
any.** At n = 20 over nine strata the floor guarantees coverage, as `asc-1bd` measured.

**The predictions, graded as registered** (nothing here is reinterpreted after the fact):

| | registered | measured | verdict |
|---|---|---|---|
| P1 | stratified ≥ +3 points, CI lower > 0 | +2.3, CI −1.7 to +6.3 | **not met** |
| P2 | ≥ +15 on classes random omitted | +13.4, CI 1.2 to 25.7 | direction held, magnitude short |
| P3 | rare classes ≥ +10 | −1.4, CI −8.3 to 4.3 | **refuted** |
| P4 | common classes: random ≥ stratified | +3.9 for stratified | **refuted** |
| P5 | both arms > 40 % accuracy | 51.9 % / 54.2 % | held |

**The decision rule fires as INCONCLUSIVE, not as a drop.** It read: drop only if the paired CI
lies entirely below +2 points; keep only if its lower bound clears +2. The interval spans it. The
mode is therefore unchanged — it is neither vindicated by a significant accuracy gain nor condemned
by a significant absence.

## Decision

**Keep `--sample stratified`; `asc-asq` closes with that decision recorded and no code change.**

Three statements, kept separate:

1. **The mode does what it says, and that is measurable.** Coverage is complete under stratified and
   incomplete under random (21 omissions in 10 draws), and on the items whose class random omitted,
   stratified scores **+13.4 points** with a CI that excludes zero. That is the mechanism, not a
   correlation: the only difference between the arms is what the sampler put in the prompt.
2. **The advantage is real but small, and it is not where the mode's case was argued.** Overall
   accuracy moves +2.3 points, 7 wins of 10, and the interval includes zero (sign test p = 0.17).
   The prediction that the RARE classes would gain most — the argument EV-12 left open and this
   bead exists to test — **failed**: −1.4 points on the three classes holding ≤10 % of the pool.
   The gains landed on the mid-frequency classes (`time_concurrency` +11.7, `assumption_audit` +9.2,
   `write_read_asymmetry` +7.1), which a random 20 under-represents without fully omitting.
3. **The drop rule does not fire.** It reads *"if stratified shows no advantage"*. Advantage was
   measured on the subset the mechanism predicts and is absent overall; that is not "no advantage",
   and dropping a mode with a measured +13.4-point effect on under-represented classes would be
   discarding a result to avoid an uncertain one.

## Confidence

**High** for the sampler facts and the corpus counts: omissions are counted, the split is disjoint
by construction and verified, and both are reproducible from the seeds.

**Moderate** for P1 and P2: 10 paired draws, one model, one corpus.

**None** for per-category recall on the rare classes as a *proportion*. `state_machine` has 17
held-out items and `data_lifecycle` 13 — both under this project's `MIN_N` of 20 — so their
per-class rows are anecdotes and P3's refutation is a refutation of the *prediction*, not a
measured absence of effect on rare classes.

## Limitations

- **The corpus is one file.** 340 of 379 findings are about `packages/core/src/handler.ts`, produced
  by one review campaign that ran each lens over copies of that tree. A difference measured here is
  a difference about findings that look like these, and the class shares are a property of that
  campaign, not of reviews in general.
- **The label is the reviewer's own lens choice**, not an external ground truth. Two reviewers can
  file one defect under different lenses; that noise attenuates every arm equally, but it shrinks
  the differences this design can see.
- **The model is pinned but not the temperature**, so a draw carries model noise as well as prompt
  noise. The pairing is on the draw, which is what the inference assumes.
- **Two of 22 calls came back with labels for only part of the test list** (84/192 and 100/192) and
  were re-run; the harness now retries any call that labels fewer items than asked. A truncated
  reply is a failed call, and counting its unlabelled items as wrong would score the sampler on the
  model's output limit.
- **Ten draws is enough to see a 2-point difference only if the paired spread is small.** It was
  not: the per-draw differences range from −9.4 to +10.4 points.

Cost: **$18.47** for the 20 scored calls, plus roughly $3 for the re-run truncated and unparseable
replies.

**Artifacts, so a later re-check does not have to re-buy the draws.** `spike/asq/run/split.json`
(sha256 `168da73a…`, the fixed split the sampler never saw) and `spike/asq/run/results.json`
(sha256 `23f30713…`, every call's prompt composition, omissions and 192 predictions) are kept beside
the harness; `spike/asq/corpus.json` is `a9837a53…`. `node spike/asq/score.mjs` reads the two run
files and reproduces every number above.
