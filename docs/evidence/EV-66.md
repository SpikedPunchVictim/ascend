# EV-66: does churn just restate the outcome?

**Status** Predictions registered 2026-10-13 in the notes of `asc-09wx.2`, before any figure below
was computed. Measured the same day.

**Question** A busy file gets more later commits, so more chances that one of them rewrites a line.
Open since EV-58: is "churn predicts a later fix" a fact about the commit, or only about how much
traffic its file gets afterwards?

## What was already known

Churn top decile 1.82 (nx, EV-60) and 1.53 (n8n, EV-58) against typed fixes, and 1.41 against any
rework in n8n (EV-62). The unregistered pattern hunt of `asc-09wx.5` had put heavy deletion at 1.35
and 1.41 and young file at 1.21 and 1.24 under size, file count, churn and type.

## Method (fixed before measuring)

- **Later activity:** per commit, the largest number of commits NOT typed `fix` that touch any one
  of its source files in the following 30 days, in buckets 0, 1, 2, 3-4, 5-7, 8+.
- **Main test:** Mantel-Haenszel risk ratio against the typed-fix outcome of EV-57, strata size
  decile by commit type, then the same with the later-activity bucket added. Thresholds are each
  repository's own quantiles. nx and n8n separately.
- **Second test, n8n only** (the one repository with every rewriter traced, EV-62): among commits
  with a line rewritten by any commit within 30 days, the share rewritten by a typed fix, churn top
  decile against the rest, stratified by size decile.

**Rule.** If churn falls below 1.3 in both repositories once later activity is held fixed, churn is
dropped as a risk signal and `asc-09wx.3` is closed as moot. If it stays at or above 1.3 in both,
it is kept.

## Predictions

- **P1.** With later activity held fixed the churn ratio is below 1.3 in both repositories.
- **P2.** It stays above 1, interval excluding 1, in at least one.
- **P3.** In n8n, among reworked commits the fix share for churn top decile is within 0.9 to 1.1
  of the rest.
- **P4.** Size top decile stays at or above 1.3 in both under the same control.
- **P5.** Young file (bottom quarter by age) falls below 1.15 in both.
- **P6.** Heavy deletion (top tenth by removed lines) stays at or above 1.25 in both.

## Decision

**The rule returns no verdict: churn restates later traffic in n8n and does not in nx.** Neither
branch of the rule is met, so `asc-09wx.3` is not closed by it. Taken with EV-63, where churn
reached only 1.24 pooled on our own repositories, churn has now failed the bar in two of the three
places it was tested with an outcome that does not flatter it. It stays out of anything built.

What the same table says about the other signals:

1. **Size is not an exposure artefact.** It keeps 2.26 and 1.97 with later activity held fixed, and
   in n8n a reworked large commit is a third more likely to have been reworked by a fix (1.35).
2. **Heavy deletion survives a control it was not designed against** (1.44, 1.48), and its fix
   share among reworked commits is raised too (1.18). It was unregistered in `asc-09wx.5`; here it
   was registered as P6.
3. **Young file predicts rework, not fixes.** It survives the control (1.40, 1.34) but its fix
   share among reworked commits is 1.00 (0.94-1.06): new files get revised, by features as much as
   by fixes. That is ordinary development, not a risk.

## Confidence

**Medium.** Two repositories, both TypeScript monorepos with labelled commits, and they disagree on
the headline. Later activity is measured after the commit, so holding it fixed may remove some real
effect (a bad commit can cause its own follow-up traffic); the test is conservative for every
feature alike. The fix-share test rests on n8n alone.
