# EV-27: can a review finding be joined to the implementer events it concerns, and where does that join live?

**Status**      Measured 2026-09-26 for `asc-gtnu`, `derive_version` 4. The recording half is built
                and green: findings have an event, a store type, and a handler. **Nothing about
                reviewers has been measured**, because `ReportFindings` has been called 0 times, and
                this record says so in every section rather than once. **Stage 0's counts were not
                numerically pre-registered** — see Predictions. One carried figure reproduced, two
                did not.

**Question**    For `asc-gtnu`, need (2), quoted: *"a join from each finding to the implementer's
                events for the same files (did it run a catchable_by check?)"*. The plan's premise
                was that this join is **backward** and **cross-stream**, and that both directions
                were absent from the DSL. The question this record actually answers, because it is
                the one the data can answer: *where does the join live, and is it expressible?*

## Method

Four measurements, all read-only, all over `~/.claude/projects` or the frozen copy `/tmp/frozen-root`
taken because this session's own writes to the live transcript directory moved the corpus under the
measurement:

1. **Stage 0's spike** (`spike/review-join/`, read-only). There is no finding data, so the stand-in
   is the reviewer itself: for each (subagent stream, absolute path it read), classify where a
   `file.changed` for that path occurs in the session — same stream (a), the session's `main` stream
   (b), another subagent stream (c), nowhere (d). Main-stream reads are the control. Deliverable:
   `spike/review-join/FINDINGS.md`.
2. **What the join can reach, as shipped.** The four `handlers/*.yaml` run under `scope: stream` and
   under `scope: session`, over `/tmp/frozen-root`, through `asc handlers check`.
3. **The backward reference's own coverage.** Four probe handlers, one per (trigger kind, before
   kind) pair, over the same corpus: `triggers` and `unsatisfiedBefore` say how often the reference
   resolved.
4. **The carried figures, re-measured.** `spike/tmp/ev27-remeasure.mjs` sweeps every transcript for
   `ReportFindings` calls and for `Agent`/`Task` spawns by `subagent_type`; the bug-hunt count comes
   from the store (`v_skill_activation_v1`).

Horizon for the frozen figures: 90 files, 90,155 records, 115,954 events, `derive_version` 4,
2026-09-12T01:07:55.847Z → 2026-09-27T00:17:37.120Z, counters `unpairedResults` 0, `unfinishedCalls` 1,
`unmatchedNotifications` 55, `syntheticModelRecords` 12, `offVocabularyFindings` 0. Horizon for the

## Result

### 1. Where the join lives — Stage 0, 831 subagent read pairs, 257 main pairs as control

```
(a) same stream          154  (18.5%)
(b) the session's main   353  (42.5%)
(c) another subagent     130  (15.6%)
(d) nowhere in session   194  (23.3%)
```

Cross-stream (b + c) is **483 of 831 (58.1%)**; a within-stream-only extension reaches **18.5%**. The
concentration check says this is not one stream's shape: 69 of 83 subagent streams contributed pairs
and the largest contributed 44 (5.3%).

The control is what makes the shape attributable: main-stream reads are joinable **within their own
stream 61.5% of the time (158 of 257)**, and 132 of those have the edit strictly before the read. A
subagent reads what another stream writes. That is the reviewer/implementer asymmetry, visible in the
data before any reviewer has reported a finding.

**The direction did not come out as the plan assumed.** Only **34 of 831 (4.1%)** admit an edit
strictly earlier than the read; **603 (72.6%)** have their editor only after it. That is the
*explorer's* shape — read first, report, then main edits — and this corpus holds no reviewers (0
`review` subagent_type spawns; 0 `ReportFindings` calls). A reviewer's shape is the mirror image,
because `catchable_by` is a question about code already written. So the SCOPE conclusion transfers
(streams partition identically whatever the role) and the DIRECTION conclusion does not.

### 2. What the shipped DSL can reach — the four handlers, both scopes

| handler | window | `scope: stream` | `scope: session` |
|---|---|---|---|
| `edit-verified.yaml` | `first` on check.run, `until: prompt.submit` | rows 2815, unclosed 55, noMatch 488 | rows **2815 (+0)**, unclosed 0, noMatch 543 |
| `edit-unverified.yaml` | `absent` on check.run, `until: prompt.submit` | rows 488, unclosed 55, noMatch 0 | rows **543 (+55)**, unclosed 0, noMatch 0 |
| `read-unused.yaml` | `until: session.end` | rows 367, triggers 2167 | **refused** |
| `subagent-outcome.yaml` | `until: session.end` | rows 44, unclosed 44 | **refused** |

**`scope: session` buys +0 to +55 rows, and for the one handler where it buys the most it is
buying the wrong thing.** The 55 windows a stream's own `session.end` used to leave unresolved are
*reclassified, not found*: a `first` window calls them `noMatch` and emits nothing, an `absent`
window emits a row for each. `edit-unverified.yaml` reports "an edit reached the next prompt with no
check run after it"; under session scope 55 more rows say that, and what actually happened is that
*another stream's* `prompt.submit` closed the window. The row's own words silently changed meaning —
"the next prompt" is no longer this stream's — and no field in the row says so. **A scope is not a
neutral widening: for an `absent` window it widens the claim, and `absent` is the mode whose row is
a claim.**

The 18.5% / 58.1% split above therefore does **not** describe what shipped. Stage 3 built
cross-stream scope; Stage 3 refused to let the backward reference use it, for a real reason (`seq`
numbers count within one stream, `packages/core/src/event.ts:15-17`, so "the event before this
trigger" across two streams would be decided by which file the replay read first rather than by which
event came first in time). The join the 58.1% describes is exactly the composition that is refused.
`asc-gtnu.7` carries that, with three ways to make it sound.

### 3. The backward reference's coverage, within a stream

Exact output, `/tmp/frozen-root`, through `asc handlers check`:

```
check.run      <- file.changed    triggers 1541   unsatisfiedBefore    5   resolved 1536 (99.7%)
file.changed   <- check.run       triggers 3358   unsatisfiedBefore  600   resolved 2758 (82.1%)
command.run    <- prompt.submit   triggers 69747  unsatisfiedBefore    0   resolved 69747 (100%)
tool.use.start <- tool.use.start  triggers 18511  unsatisfiedBefore   90   resolved 18421 (99.5%)
```

So the construct is not speculative: where a prior event of the right kind exists in the stream, it
is found 82–100% of the time. What is unmeasured is whether a **reviewer's** backward join is the
join to build, and this corpus cannot say — the direction split in §1 is the explorer's. The
construct ships as **capability with an unmeasured-for-reviewers note**, per the plan.

### 4. The unsatisfiable case, which is the common case

Stage 0's (d) — no `file.changed` for that path anywhere in the session — is **194 of 831 (23.3%)**
of subagent pairs and **98 of 257 (38.1%)** of the main control: read-only subjects, docs, config,
other repositories. A join that cannot be satisfied must be **reported as unsatisfiable, never
emitted as a zero-valued row**, which is `asc-6ola.9`'s silent-zero class. It now is: an
unsatisfied `before:` is counted as `unsatisfiedBefore` (5, 600, 0, 90 above) and a window decided
with no match is counted as `noMatch`. Measured on the same corpus, **488 of `edit-verified.yaml`'s
3,358 triggers (14.5%)** were already decided-no-match and counted by nothing before this work — see
`dogfood/0018` and `asc-gtnu.6`.

### 5. Two instrument findings that outlive this record

**`check.run` cannot be joined to a file at any scope.** Read off its events and confirmed against
the declaration, its field set is `runner`/`verdict`/`verdict_state`/`verdict_source` plus the
envelope — **there is no `path`.** So "did the implementer run a `catchable_by` check on THIS file"
is not derivable, in-stream or cross-stream, and Stage 3 does not change that.
`handlers/edit-unverified.yaml` asks only "did ANY check run after this edit", which is a different
question. Filed: `asc-gtnu.10`.

**The log and the entries disagree about the same facts.** `review_finding.reviewer_model` is filled
by the deriver from the record's own `message.model`, and the `review.finding` event has **no such
field** (`packages/core/src/event.ts:141-151`) — so no handler over the log can stratify findings by
reviewer model, which is the side a dry run reads. `line` has the mirror-image asymmetry: the event
holds a number and the handler row renders it as text, because the DSL runs every reference through
`String(raw)` (`packages/core/src/handler.ts:566`). Filed: `asc-gtnu.11`.

### 6. The handler

`handlers/review-finding.yaml` — one row per finding, `judged: [catchable_by]` declared and never
carried. It reports **0 rows over this project's corpus, measured**: 0 triggers of
`review.finding` in 115,954 events. That zero is stated in its header as the measured state, not left
to look like a working handler. Its path is exercised end-to-end by a fixture
(`packages/cli/test/handlers-check.test.ts`, a synthetic `ReportFindings` call carrying two findings,
one of them outside the nine lens slugs) because nothing else can exercise it.

## Limits

- **No reviewer has ever reported a finding.** 0 `ReportFindings` calls across 1,236 files and
  640,404 records, re-measured for this record. Every claim about the finding→implementer join is
  about a stand-in (a subagent and the paths it read) and every test of the path is a fixture's.
- **The direction question is unanswered and this record does not answer it.** 4.1% backward here is
  the explorer's shape. `asc-gtnu.8` owns the test, with its predictions pre-registered.
- **One operator, one machine, n = 1 project** for the 831 pairs, and it is a **CENSUS** of those
  pairs rather than a sample — no interval is computed and no Wilson is quoted, because `MIN_N`
  governs a grouped proportion and this is a count over a whole population.
- **The corpus is live.** `records` moved 637,258 → 640,404 between the plan's sweep and this one;
  `files` was 1,236 in both and spawns 1,063 in both.
- **The basename-variant figure in `spike/review-join/FINDINGS.md` recovers 14 pairs (1.7%) and is an
  upper bound, not a measurement** — it cannot tell a spelling difference from two same-named files
  in different directories. All 2,142 read paths are absolute, so the exact-path column is the honest
  one.
- **`scope: session` was measured on 4 handlers, not 9 × 12 shapes.** The earlier "+0 to +3 across 12
  synthetic shapes" is superseded by §2 and understated the effect for `absent` windows; the
  corrected number is on 4 real handlers, and the other two shipped handlers cannot be scoped at all
  without changing their `until`.
- **An untested assumption is carried forward:** that a reviewer reports on what it read. That is
  what `asc-gtnu.8` would test.
- **The 377 is unexplained.** Its denominator is plausibly the same population and its numerator is
  not, and I did not determine the method that produced it. Saying so is the record; guessing a
  reconciliation would not be.

## Decision

**The recording half is accepted and ships at `derive_version` 4.** A finding has an event
(`review.finding`, one per element of `findings[]`), a store type (`review_finding`, with the nine
lens slugs as its one closed vocabulary), a producer in the deriver, and a handler. `EVENT_DERIVE_VERSION`
moved 3 → 4 for it, which by its documented meaning moves counts with no handler changed.

**The join is expressible in one direction and one scope, and neither is the one the plan assumed.**
Cross-stream scope shipped (`scope: session`) and is worth +0 to +55 rows on the four shipped
handlers, with the larger figure being a mode whose meaning it changes. The backward reference
shipped (`before:`) and resolves 82–100% of the time where the prior event is in the stream. **The
composition — backward AND cross-stream — is refused**, and the refusal is a property of the log's
numbering rather than of the implementation.

**`asc-gtnu` closes as "the recording half is built and the join is expressible; the experiment is
not run" — not as delivered.** 0 findings means Stages 1–4 can be complete and green while nothing
has been measured about reviewers, and the plan says so in its own Risks.

**Filed, not dropped:** `asc-gtnu.7` (the backward cross-stream join, with three ways to make it
sound), `asc-gtnu.8` (the seeded-defect recall experiment, with five pre-registered predictions and
its size fixed at 100 seeds / 24 reviewer runs before collection — it also owns the direction test
and blocks `.7`), `asc-gtnu.9` (`ARCHITECTURE.md:285` rules out a `Stop` channel that
`spike/exposure/FINDINGS.md:15` measured delivering 2/2), `asc-gtnu.10` (`check.run` has no `path`),
`asc-gtnu.11` (`review.finding` carries no reviewer model), `asc-gtnu.12` (a `file.changed` field
named `before` is shadowed by the `${before.*}` namespace), and `asc-gtnu.6` (the decided-no-match
silent zero, closed fixed in `25d4504`).
