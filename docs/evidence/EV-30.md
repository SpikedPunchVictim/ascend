# EV-30: does a task that ASKS for a record produce one?

**Status**        Measured 2026-09-28 for `asc-4so.3`. The question, the task string, the two arms,
                  the model pin, the spend ceiling and four predictions were written into that
                  bead's notes on 2026-09-25, before any prompted-recall session ran. **P1 and P3
                  hold; P2 is consistent but ran at n = 2; P4 is supported. One pre-registered
                  RATIONALE is refuted**: P1 justifies its threshold with "the brief names both the
                  command and the types" — the brief names the types and never the command.
                  **Arm G ran two sessions, not three**: the spend ceiling refused the sixth.

**Question**      EV-16 measured UNPROMPTED recall and found it zero — 0 of 15 sessions across five
                  availability conditions, no `asc` invocation of any kind. Its task was deliberately
                  neutral, so it could not exclude the explanation that the task simply did not WARRANT
                  a record. This asks the complementary question: does a task that asks for a record
                  produce one? If it does, the brief does not cause recording but the tool is usable
                  when a session intends to record, and the product needs a TRIGGER rather than a
                  better brief. If it also fails, the problem is in the recording path itself.

## Method

Script: `spike/ev16-arms.mjs`, arms `F` and `G`, which the uncommitted harness change adds for this
bead alone. The harness is otherwise EV-16's, run as written.

```
EV16_MODEL='glm-5.3-flash:cloud' EV16_MAX_USD=3 EV16_ARMS=F,G EV16_REPS=3 \
EV16_TASK="Read calc.js, find and fix the bug in median(), then run the tests. When you are done, \
record an entry about what you did in this project's store." \
node spike/ev16-arms.mjs
```

- **Task, verbatim from the pre-registration, byte-identical in both arms.** It names the GOAL,
  never the tool or the command. Dictating `asc record` would measure command-following, not the path.
- **The only difference is the hook.** F installs the real `asc install-hook`; G does not. One
  `mkdtemp` scratch project per session, its own store, its own `.claude/settings.json`.
- **Grant**, identical in both arms: `Read,Edit,Write,Bash(node test.js),Bash(asc:*)`, `dontAsk`.
  `Bash(asc:*)` is present in G too — the command is PERMITTED in both arms; only the brief varies.
- **Success is read off the STORE**, never off the agent's report: entries with `source = 'self'`
  in the scratch store, via `asc query --json`.
- **A session with no billable envelope stops the run** (exit 3). That guard was added after the
  void 2026-09-25 attempt, where the harness exited 0 over six `is_error` sessions.
- **The store is polluted by the hook and the outcome is separated from it.** The hook runs
  `asc ingest claude-code` at `SessionStart`, which sweeps `~/.claude/projects` into the fresh
  scratch store. `asc record` writes `source = 'self'`; ingest writes `'derived:claude-code'`. Both
  are reported; only `self` is an outcome.

## Predictions (verbatim from the bead, frozen 2026-09-25)

- **P1** (primary, arm F): prompted+hook produces a record in **>= 2 of 3** sessions.
- **P2** (arm G): prompted+no-hook is LOWER than F: **0 or 1 of 3**.
- **P3** (friction): among recording sessions, **>= 1** shows visible path friction (a refused or
  failed first attempt, or a scratch envelope file).
- **P4**: F > G would re-confirm EV-16 P4 (the hook raises the rate) at a non-zero floor;
  F = G = 3/3 would weaken the hook claim to availability-only.

### What decided F2, and it is not comprehension

F2 fixed the bug, ran the tests, then spent its remaining effort looking for the recording command
and never found a form it was allowed to run. Its `Bash` invocations, in order:

```
find …/.ascend …/.claude …/.shim -type f | head -50
file .ascend/ascend.db && cat .shim/asc && echo "---" && cat .claude/ascend-hook.sh
.shim/asc --help 2>&1 | head -60                              DENIED
/opt/homebrew/Cellar/node@24/24.18.0/bin/node /Users/…/packages/cli/dist/bin.js --help   DENIED
.shim/asc say --help 2>&1 | head -40                          DENIED
sqlite3 …/.ascend/ascend.db ".tables" 2>&1                     DENIED
```

and its verbatim closing message:

> The bug fix and tests are done, but I've hit a wall on the final step and am stopping per the
> three-attempt rule.

It read `.shim/asc` — `exec "/opt/homebrew/Cellar/node@24/24.18.0/bin/node" "/Users/…/packages/cli/dist/bin.js" "$@"` —
learned the absolute invocation, and pursued that form. **It never tried the bare command `asc`,
which is the one form the grant allows.**

The two sessions that recorded did so by a different route: `ls -R` / `find` showed them a `.shim`
directory, and each then tried bare `asc --help`, which ran. F3 tried `.ascend/../.shim/asc --help`
first, was denied, and recovered by trying `asc`. That denial is P3's friction.

## What it means

**Prompted recall works.** The branch the bead named for a non-zero result is the one that fired: the
brief does not cause recording, but the tool is usable when a session intends to record. Combined
with EV-16's 0 of 15, the finding is that **the ask is the trigger, not the brief** — the product
needs a moment that makes a session intend to record, rather than a better brief.

But the qualification is the more actionable half, and it is not about the model's willingness:

- **The brief never names the recording command.** Every line is `<type> -- <record_when>`; the only
  `asc` strings in it are `asc ingest claude-code` and `asc query`, both incidental prose inside
  derived types' "never by hand" text. So a session told to "record an entry in this project's store"
  must discover the command. P1's stated rationale assumed otherwise.
- **The discovery artifacts point at a form the allowlist denies.** The shipped
  `.claude/ascend-hook.sh` resolves its binary preferring `$root/packages/cli/dist/bin.js` and runs it
  as `node "$bin"`, while `ARCHITECTURE.md` names `Bash(asc record:*)` as the allowlist entry that
  makes recording frictionless. A session that discovers the tool by reading its own installed hook
  script — the natural path when the brief is silent — learns the absolute form. That is the form F2
  took, four times, and it is refused.

So the rate this run measures is depressed by a discovery defect that is not the model's. The honest
reading of 2 of 3 is: **the recording path works when a session finds it, and two of three sessions
found it by luck of which artifact they read first.**

## Limits

- **Arm G ran 2 sessions, not 3 — the pre-registered design was not completed.** `EV16_MAX_USD=3`
  was refused at G3. Total spend was **$3.2169350000000003**, so the ceiling was *crossed*, not
  held: it gates on what has already been spent, not on a projection. Sized from EV-16's measured
  ~$0.14/session, it did not fit this route's cost.
- **Cost per session is 4.6x the figure the ceiling was sized from.** Measured $0.4508–$0.82172,
  mean $0.64339 over n = 5, against ~$0.14/session on `claude-haiku-4-5-20251001` in EV-16. The
  pre-registration's ceiling was sized on the stale number.
- **The 0-of-2 in G is an anecdote, and it is not a proportion.** n = 2 against `MIN_N` = 20. The
  bead's own escalation rule applies: if F is non-zero, n goes to >= 5 per arm before any proportion
  is quoted. This record quotes no proportion.
- **Comparability with EV-16's 0-of-15 floor is broken**, exactly as the 2026-09-25 amendment
  pre-declared: this route has no dated Anthropic model id, so the run is `glm-5.3-flash:cloud` and
  the unprompted floor it contrasts against was a different model. Nothing here is a haiku comparison.
- **Single model, single task, fresh-store scenario only.** Every session began with an empty store
  and a one-file project.
- **`costBasis: unknown`** on every envelope. The `costUSD` figures are what the gateway reported;
  they are not reconciled against a price list.
- **P3's "or a scratch envelope file" clause was not exercised.** Friction is reported from denial
  records and command order, not from a temp file the harness never looked for.

## Decision

The measurement answers `asc-4so.3` and it is closed by this record. Two consequences follow, and
neither is a change to the brief:

1. **File the discovery defect.** The brief names types but not the command, and the installed hook
   script — the artifact a session naturally reads to find the command — advertises an invocation
   form the documented allowlist denies. This is a defect in a shipped artifact, found because a
   measurement was running and nobody was looking for it.
2. **`asc-4so.3`'s escalation rule is not triggered as written**, because the rule escalates on F
   being non-zero and F is 2 of 3. Any further spend on a proportion should wait until the discovery
   defect is fixed, since a rate measured through it is a rate on a path that two sessions in three
   reached by accident.

The next rung this feeds is `asc-eve4` (deliver guidance at the event): EV-16 says session-start text
does not change behaviour, and this says the ask does. A trigger placed at the moment of the work is
the shape those two results point at.
