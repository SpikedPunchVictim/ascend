# EV-79: what does the commit-risk arm size to on the project it is installed in?

**Status**      Measured 2026-10-28 for `asc-8wpl` and `asc-09wx.19`. **No predictions were
                pre-registered**, and this record does not claim to be a pre-registered reading:
                it is `EV-77`'s registered parameters applied to a rate measured on the
                population the experiment actually accrues on. The owner then chose the re-size
                over widening the install (decision recorded on `asc-8wpl`).

**Question**    `EV-77` sized the commit-risk nudge at 662 units / 65 active days for a 30%
                reduction, on 10.1875 units per active day, baseline 0.78119, design effect
                5.28545. That rate was measured over **the eight repositories** in the rework
                corpus. `handlers/commit-risk-nudge.yaml` is installed in **one**. What does the
                same experiment need, and what can it detect in a fixed horizon, at this
                project's own rate?

## Method

Read-only against this project's transcripts and the installed hook.

```
grep -rl 'ascend-hook.sh' --include=settings.json ~/projects
node packages/cli/dist/bin.js handlers power handlers/commit-risk-nudge.yaml \
  --effect 0.3 --project -Users-spikedpunchvictim-projects-ascend
```

`handlers power` reports `units 93`, `active_days 24`, and then refuses to plan: `units` equals
`successes` on a `say:` handler, so `whyNot` stops on the identity before any arithmetic runs
(`asc-xg62`). **So the RATE comes from that command and the DAYS come from `EV-77`'s parameters
applied by hand** — the two halves are not one tool's output, and the split is stated here rather
than left to be inferred from a table.

Rate: 93 units / 24 active days = **3.875 units per active day**, against `EV-77`'s 10.1875.

The arithmetic is the continuity-corrected two-proportion test (`z` 1.959964, power 0.841621,
baseline `p1` 0.78119, `p2 = p1·(1 − reduction)`, equal arms, times design effect 5.28545).
**As a check on the formula rather than a claim about it**, re-deriving `EV-77`'s own two
registrations from its own parameters returns its own two numbers:

```
reduction 30%: per-arm 62.57, total units 662, days at 3.875 = 171
reduction 50%: per-arm 23.75, total units 252, days at 3.875 = 66
```

662 and 252 are exactly what `EV-77` registered, so the same function is being asked the new
question rather than a differently-shaped one.

## Measurement

At this project's 3.875 units per active day:

| reduction | units needed | active days |
|---|---|---|
| 50% | 252 | 66 |
| 42.2% | 349 | **90** (the default horizon) |
| 30% | 662 | 171 |

The same run, asked what is detectable in a fixed horizon:

```
90-day budget: 348.8 units = 32.99 per arm before deff
detectable reduction at 90 active days: 42.173%
  30 active days -> 72.4% reduction
  60 active days -> 52.0% reduction
  90 active days -> 42.2% reduction
 180 active days -> 29.2% reduction
 365 active days -> 19.9% reduction
```

## Decision

**The experiment is re-sized to this project's rate.** `asc-09wx.19`'s target is now:

- **66 active days for a 50% reduction** — within a day of the 65 active days `EV-77` gave a 30%
  reduction, a coincidence of this project's rate landing at almost exactly 0.38 of the corpus
  rate;
- **171 active days for a 30% reduction**, not 65;
- and at the default 90-active-day horizon the arm can separate **no smaller than a ~42%
  reduction**. A registered 30% effect is not reachable inside a quarter.

The alternative — installing the hook in the repositories `EV-77` counted — was declined
(`asc-09wx.13` ruled it out, and `asc-8wpl` records the tradeoff). What that costs is now a
number rather than an impression: the same experiment is 2.63× slower on one project than on the
corpus `EV-77` measured.

## Confidence

**High** in the rate: 93 and 24 are two rows of one command, and the command is the instrument
`EV-72` used.

**High** in the arithmetic, because it reproduces `EV-77`'s two registrations exactly from
`EV-77`'s own parameters. A formula that could not return 662 and 252 would have been a new
method wearing an old record's numbers.

**Medium** in the design effect, which is `EV-77`'s and is carried unchanged. It was estimated on
29 session clusters; this project alone has fewer, and a design effect estimated on more clusters
is the more stable of the two. Carrying it unchanged is the conservative direction only if the
true value is not smaller — nobody has estimated it on one project, and this record does not.

**Not measured here at all:** whether the rate holds. 24 active days is a month of one person's
commits, and `EV-77`'s own note is that this corpus moves.
