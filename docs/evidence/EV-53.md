# EV-53: does pattern-hunt over a CSV export find what `asc stats` found, or more?

**Status**      Measured 2026-10-13 for `asc-heqy`. Predictions were written to the bead's notes
                before the agent was launched. They were not sealed by hash; the bead history is the
                record of their order. P1 to P4 held, and the result that matters is one no
                prediction named: the skill corrected two findings this series had recorded.

**Question**    Given only CSV exports of the non-invalidated `tool_denial` (859 rows) and
                `verification_run` (1,702 rows) entries, does a fresh agent running the
                `pattern-hunt` skill rediscover what EV-3 and EV-19 found with ascend's own analysis
                layer, and does it find anything they missed?

## Method

Two `asc query --csv` exports: `project, session_id, occurred_at, denial_kind, tool_name` and
`project, session_id, occurred_at, runner, verdict, verdict_source, previous_verdict`. One agent,
given the two files, a one-paragraph description of each, and the skill. It was told not to read
this repository, its store, or `~/.claude/projects`, and it reports that it did not.

The reference set is the findings a CSV can show:

- **A1** denial kind concentrates by project (EV-19 #1)
- **A2** `automode-unavailable` is a new, now-dominant mode from September (EV-19 #2)
- **A3** `automode-blocked` has no project signature (EV-19 #3)
- **A4** the corpus holds rows from harness or ephemeral projects (EV-19 #4)
- **A5** weekday and time pairings are which-sprint-when, with 2026-09-03 an outlier day (EV-3)
- **A6** Bash carries about nine in ten denials (EV-19)

One run, one agent, one corpus. The export left out `tool_use_id`, so rows that are distinct events
in the store can be identical rows in the file.

## Result

The agent's own accounting: about 35,800 scan comparisons, 21 hand tests with a p-value (5 survive
Benjamini-Hochberg at 5%), about 18 residue checks, six findings reported as measured.

| Reference | Found? | What it reported                                                                                                                                       |
| --------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A1        | yes    | "Project predicts refusal kind (Cramér's V = 0.46)", classed as first-pass material. EV-3 measured 0.465.                                               |
| A2        | yes, and corrected | 125 of 176 `automode-unavailable` rows come from one session, 2026-09-12 to 09-17.                                                          |
| A3        | no     | Not reported.                                                                                                                                          |
| A4        | yes, and extended  | 17 of 58 denial sessions are harness runs; one fixture row dated 2026-01-02 in `verification_run`; 3 rows duplicated across two sessions.   |

New to this series, as the agent reported them and not re-verified here:

- Permission-rule refusals in the grizzly projects run at about 5 a day and are not fading (5.7 then
  4.9 per day across halves, rho -0.06, p = 0.67). This agrees with EV-52.
- Inside the one long session's `automode-unavailable` bursts, 0 verification verdict changes
  against 12.8 expected (p = 0.007): work stalls while refused calls are retried.
- 44% of consecutive same-session, same-runner `verification_run` rows repeat the verdict, so the
  exported table cannot support per-runner failure rates or time-to-fix.
- Verdicts read from exit status are fixes 64 to 20; read from output, 731 to 727. How a verdict
  was read depends on what it was.

## Decision

**A general skill over an adapter export did this job at least as well as the analysis layer did,
and its provenance lens found what `asc stats` has no mode for.** It recovered four of six
reference findings outright and a fifth in part, missed one, and corrected two:

1. **EV-3's outlier day is one instant.** EV-3 recorded 2026-09-03 as 143 denials, 35% of its
   corpus, and treated it as a day. 127 of them are tool calls refused within 59 ms in one session,
   which reads as one interruption cancelling queued calls. Counted as events they are 127 user
   rejections; counted as decisions they are one.
2. **EV-19's "single largest behavioural change in the corpus" is mostly one session.** 125 of 176
   `automode-unavailable` rows are one six-day ascend session.

Three consequences for the product question that prompted this.

- **The case for `packages/analysis` as a differentiator narrows.** Nothing in the agent's report
  needed it. What the skill did need, and did not have, was denominators and content.
- **The tables are the limit, not the method.** Roughly 35,800 comparisons produced two
  actionable findings and four warnings about what not to act on. Neither table records allowed
  calls or unchanged check runs, and neither carries the command text, so no rate exists and "which
  rule" cannot be asked.
- **The adapter's filtering cost the analysis.** `verification_run` keeps verdict changes only,
  which is why the agent could establish no failure rate and classed its tempo finding as partly
  true by construction. The normalized event stream carries what the entries dropped.

## Confidence

**High** for the two corrections: both re-measured on the live store. **Medium** for the comparison
itself: one run of one agent, and a second run could find A3 or miss A2. **Not assessed** for the
agent's other figures, which are quoted and not re-run.

**Limitations.** The reference set was chosen by the author of the predictions. The agent ran a
different model session with a different budget than the sessions that produced EV-3 and EV-19, so
this compares outcomes, not methods at equal cost. The export's missing `tool_use_id` shaped one of
the agent's findings.
